一、第6章 运算符与表达式（00:00:07—02:25:16）

00:00:07—00:10:56 ｜ 表达式总览、自增自减与运算符优先级

本段是本章的引入。老师先回顾已学过的表达式类型：前面四节课已经学过赋值表达式、关系表达式、逻辑表达式。今天要新增的是条件表达式、逗号表达式，还有位运算；其中条件表达式（三目）有用但不算最重要，逗号表达式（位运算）在视频压缩等场合很重要；而算术、关系、逻辑等前面四类仍然是最基础、最重要的。

接着复习了算术表达式的运算符：双目算术运算符有加、减、乘、除、取余，其中取余 % 只能用于整数；单目算术运算符有取相反数（负号 -）、取正号 +，以及自增 ++、自减 --。

例题/证明 1（00:02:21）｜ 自增自减运算符：表达式的值、副作用与单目右结合

题目／任务：说清 ++x、x++ 与 --x、x-- 的语义区别，以及它们在优先级和结合性上的特点。

思路（以课件 ch06 第 69—71 页的表述为准）：

  • 自增 x++ 与 ++x 的作用都是把 x 的值加 1；自减 x-- 与 --x 都是减 1。
  • 区别在表达式的值：x++（后置）先取 x 的老值作为整个表达式的值，再执行 x = x + 1；++x（前置）先执行 x = x + 1，再取 x 的新值作为表达式的值。
  • ++、-- 要改变操作数的值，所以操作数只能是变量（或将来学到的数组元素、指针指向的元素），++3、(i+x)-- 都是非法的。
  • 优先级：++、-- 是单目运算符，优先级高于所有双目运算符。
  • 结合性：单目运算符一律从右往左结合。例如老师举例“-x++ 等价于 -(x++)”，若 x=6，则 -x++ 的值为 -6，之后 x 变成 7。

结论：凡是表达式都有值；自增自减必须作用于变量；单目运算符右结合，且优先级高于双目。

易错点：把 x++ 与 ++x 的表达式值记反；把自增自减用在常量或非左值表达式上。

本段还给出优先级与结合性的总体规律（课件 ch06 第 70 页）：

  • 圆括号 () 优先级最高，可改变优先级。
  • 单目运算符（如 !、-、++、--）优先级高于双目，双目高于多目。
  • 一般规律：算术运算 > 关系运算 > 逻辑运算 > 赋值运算。记法是从小学到初中的学习顺序——先学加减乘除，再学比较大小，再学对错（逻辑）。
  • 同级运算符的结合性：单目运算符和赋值运算符从右往左结合；其余（占大多数）从左往右结合。

00:10:56—00:18:55 ｜ 赋值表达式与复合赋值

本段讲赋值表达式及其求值与结合性（课件 ch06 第 73—75 页）。

赋值表达式的形式是 变量 = 表达式：先计算右侧表达式的值，赋给左侧变量；若类型不一致，编译器会插入一段代码做类型转换，转换不了则编译报错。赋值表达式本身也有值——就是左侧变量所拿到的值（凡表达式都有值）。

复合赋值运算符有 +=、-=、*=、/=、%= 等，是缩写。老师特别强调：x += 5 等价于 x = x + 5；但 x *= x + 2 等价于 x = x * (x + 2)，而不是 x = x * x + 2，因为右侧整个表达式要先作为一个整体计算。

例题/证明 2（00:15:57）｜ 赋值表达式的右结合：x = y = z = 3 与 x = y += z = 3

题目／任务：说明为什么赋值表达式必须右结合。

过程（按课件 ch06 第 74 页逐条还原）：

  1. x = y = z = 3; 等价于 x = (y = (z = 3));。若从左往右结合则无法解释，所以只能右结合：先算 z = 3（值为 3），再 y = 3（值为 3），最后 x = 3。
  2. 老师又举 x = y += z = 3;，等价于 x = (y += (z = 3));。
  3. 反例：x = y + z = 5; 等价于 x = ((y+z) = 5);，而 y+z 不是可赋值的变量（左值），无法执行，所以这是错的。

结论：赋值运算符优先级极低（倒数第二），且从右往左结合；不要把右边写错成“先加再整体赋值”的形式。

易错点：复合赋值时漏把右侧括起来整体运算；误以为 x = y + z = 5 合法。

00:18:55—00:24:44 ｜ 关系表达式及数学写法陷阱

本段讲关系表达式（课件 ch06 第 75—77 页）。关系运算的结果是逻辑值：成立为 1，不成立为 0。

关系运算符分两级：大于、小于、大于等于、小于等于为同一级（较高）；等于 ==、不等于 != 为另一级（较低）。举例：a > b == c 等价于 (a > b) == c；d = a > b 等价于 d = (a > b)；ch > 'a' + 1 等价于 ch > ('a' + 1)；d = a + b > c 等价于 d = ((a + b) > c)。

例题/证明 3（00:21:22）｜ 数学式 3 <= x <= 5 在 C 语言中的陷阱

题目／任务：解释为什么写 3 <= x <= 5 在 C 里不符合数学直觉。

过程（课件 ch06 第 75—76 页）：

  1. 3 <= x <= 5 在 C 中等价于 (3 <= x) <= 5——因为 <= 同级、从左往右结合。
  2. 先算 3 <= x，结果只能是 0 或 1；而 0 或 1 永远小于等于 5，所以整个表达式永远为真（值为 1）。
  3. 这与数学里“x 在 3 到 5 之间”完全不同；要在 C 里表达区间必须用 x >= 3 && x <= 5。

结论：数学上的连写不等式不能直接照搬到 C；关系表达式结果只能是 0/1。

易错点：把 C 的关系表达式当成数学连不等式；这是初学者最常犯的错误之一，老师特别提醒“希望同学们都不要犯”。

00:24:44—00:34:10 ｜ 逻辑表达式与短路规则

本段讲逻辑运算（课件 ch06 第 78—84 页）。逻辑与 &&、逻辑或 ||、逻辑非 !；逻辑值用整数表示，1 为真、0 为假。优先级：逻辑非（单目）最高，然后是算术、关系、&&、||，最后是赋值；&& 高于 ||，且都符合语言习惯。&&、|| 从左往右结合，逻辑非从右往左结合。

逻辑运算有一个重要性质——短路规则：

  • exp1 && exp2：先算 exp1，若为 0，整个表达式已确定为 0，立即停止，不再算 exp2。
  • exp1 || exp2：先算 exp1，若为 1，整个表达式已确定为 1，立即停止，不再算 exp2。

老师强调：先结合的顺序和真正执行的顺序是两码事——最外层决定先算哪一侧，能提前定值的就不再算另一侧（课件 ch06 第 83—84 页）。

此处还引入一个复杂表达式求值的例子（00:29:00，老师用具体数值推导 x++ + ++x - ++x 的执行结果），说明表达式求值除了结合顺序，还涉及运行期先算左子树还是右子树的顺序问题，并由此给出忠告：尽量写简单的表达式，不要写复杂表达式。

00:34:10—00:50:17 ｜ 短路规则的程序演示与应用

例题/证明 4（00:38:42）｜ 逻辑短路演示程序（fa / fb）

题目／任务：用两个会打印字符并返回 1 的函数，直观演示 && 与 || 的短路行为。代码逐字符取自课件 ch06 第 82—83 页。

int fa()
{
printf("A");
return 1;
}
int fb()
{
printf("B");
return 1;
}
if( fa() && fb() ) printf("C\n");
if( ! fa() && fb() ) printf("C\n");
if( fa() || fb() ) printf("C\n");
if( ! fa() || fb() ) printf("C\n");

输入：无。

输出／运行结果（课件 ch06 第 83 页给出）：

ABC
A
AC
ABC

逐行解释（课堂还原）：

  1. fa() && fb()：fa() 先执行，打印 A 并返回 1；因左侧为真，还需算右侧 fb()，打印 B 后条件成立，打印 C → ABC。
  2. !fa() && fb()：fa() 打印 A 返回 1，取非得 0，左侧已假，右侧 fb() 被短路，不再执行 → 只输出 A。
  3. fa() || fb()：fa() 打印 A 返回 1，左侧已真，fb() 被短路 → AC。
  4. !fa() || fb()：fa() 打印 A 返回 1，取非得 0，左侧为假，须算右侧 fb() 打印 B，再打印 C → ABC。

结论：&& 左侧为假、|| 左侧为真时，右侧不执行；先结合 ≠ 先执行。

易错点：初学者常误以为“先结合的先执行”，从而猜错输出。

例题/证明 5（00:50:10）｜ 短路规则的常见写法应用

题目／任务：把“判断 x 是否为零／不为零、x 与 y 不同时为零”写成 idiomatic 的逻辑表达式（课件 ch06 第 84 页）。

过程：

  • x 为零：x == 0 或 !x。
  • x 不为零：x != 0 或 x（老练写法直接写 x）。
  • x 和 y 不同时为零：!(x == 0 && y == 0)、x != 0 || y != 0、或直接 x || y。

结论：这些写法结果是等价的，但老师提醒：若 A 里包含函数调用（如前面 fa/fb），数学上等价的两式实际执行次数可能不同——例如把 A && B 改写成等价的 B && A，当 A 是带副作用的函数时，调用次数会变。这正是程序设计比单纯记语法难的地方（老师还结合第五章学过的 static 静态变量举例：同一函数两次调用，因内部静态变量状态不同，返回值可能不一样）。

00:50:17—01:00:48 ｜ 条件表达式（三目运算符）

本段讲条件运算符 ? :（课件 ch06 第 86—87 页）。形式为 exp1 ? exp2 : exp3：先算 exp1，为真则整个表达式的值为 exp2 的值，否则为 exp3 的值。它很像 if-else 语句。

例题/证明 6（00:57:50）｜ 用条件表达式求最大值、最小值与三者最大

题目／任务：用三目运算符写出取两数最大、两数最小、三数最大的式子（代码逐字符取自课件 ch06 第 87 页）。

y = a > b ? a : b;
/* 将a,b的最大值赋值给y*/
y = a < b ? a : b;
/* 将a,b的最小值赋值给y*/
/* 将a、b、c中的最大值赋值给y */
y = a > b ? (a>c?a:c) : (b>c?b:c); /* 嵌套*/

说明：a > b ? a : b 即“若 a>b 取 a，否则取 b”，把 a、b 中较大者赋给 y；三数最大则在嵌套一层比较。

易错点：条件表达式本质是表达式而非语句；不要和 if-else 混为一谈。老师还提示：嵌套条件表达式的括号不是必须的（条件运算符本身从右往左结合），但可读性上建议加括号，不要钻这种“小花招”。

01:00:48—01:09:18 ｜ 条件表达式的结合性与嵌套

本段进一步讲条件运算符的结合性（课件 ch06 第 87—88 页）：条件运算符从右往左结合。以 y = a > b ? a > c ? a : c : b > c ? b : c; 为例，正确分组为：

第1步 y = a > b ? a > c ? a : c : (b > c ? b : c);
第2步 y = a > b ? (a > c ? a : c) : (b > c ? b : c);

而“从左开始结合”的下列分组是错误的：

y = (a > b ? a : a > c) ? c : b > c ? b : c;

运算时仍按条件表达式规则（先判断最外层 a > b）从左到右求值。老师明确表态：不鼓励花精力在这种小技巧上，核心是会用 ? : 即可。

01:09:18—01:27:53 ｜ 逗号表达式与字符处理

本段讲逗号表达式（课件 ch06 第 90—93 页）。逗号表达式形如 expr1, expr2, …, exprN，依次计算，并把最后一个子表达式 exprN 的值作为整个逗号表达式的值；逗号运算符优先级最低。老师举例：int a, b, c; a=2, b=3, c=a+b;（课件 ch06 第 92 页）。

逗号表达式的一个用途是在 for 语句的初始化/更新表达式里一次初始化或更新多个变量（课件 ch06 第 91 页）：

例题/证明 7（01:10:42）｜ 用逗号表达式改写 for 循环

题目／任务：把原本在循环外分别初始化的语句收进 for 的表达式里（代码逐字符取自课件 ch06 第 91 页）。

过去分开写：

sum = 0;
k = 0;
for( j = 0;
j<100; j++) {
sum += j * k;
k += 2;
}

用逗号表达式可以写成：

for( sum = 0, j = 0, k = 0;
j<100; j++, k+=2)
sum += j * k;

老师也直言：他本人并不大喜欢把句子写得这么长，但作为 for 初始化多个变量的手段是可用的。

例题/证明 8（01:12:33）｜ 读入一行字符，统计以空格分隔的单词个数

题目／任务：读入一行字符（直到换行符为止），统计其中由空格分隔的单词个数。代码逐字符取自课件 ch06 第 92—93 页 [例6-5]。

int cnt = 0, word = 0;
char ch;
printf("输入一行字符：");
while( (ch = getchar()) != '\n' ) {
if( ch==' ' ) // 单词分隔符
word = 0; // 清除单词标志
else if( word==0 ) {// 开始新的单词
word = 1; // 设置单词标志
cnt++;
// 增加单词个数
}
}
printf("单词个数=%d\n", cnt);

思路（课堂还原）：关键是“单词数量增加的特征”出现在“空格 + 非空格”这一组合上。word 标志有两种含义：word == 0 表示前一个字符是空格（当前处于“无单词/空格状态”），word == 1 表示刚进入一个新单词。为处理行首顶格没有前导空格的情况，令初值 word = 0（等于假设上一次处理的是空格），这样第一个字母也能被正确计数；后续若遇非空格且 word==0，就说明开始了一个新单词，cnt++ 并把 word 置 1。

编译运行：用 gcc/Dev-C++ 编译运行，输入一行（如 hello world zju），回车后输出 单词个数=3。

易错点（课件 ch06 第 93 页专门提示）：不能把 while 写成 while( ch = getchar() != '\n' )——因为 != 优先级高于 =，会先算 getchar() != '\n' 得到逻辑值再赋给 ch，导致逻辑错误；必须加括号：while( (ch = getchar()) != '\n' )。

01:27:53—01:50:42 ｜ 位运算：位逻辑与移位

本段讲位运算（课件 ch06 第 94—103 页）。位运算定义在整数类型（含字符类型）数据上，分两类：

  • 位逻辑运算：按位反 ~、按位与 &、按位或 |、按位异或 ^，每一位独立进行、位与位之间互不影响。
  • 移位运算：左移 <<、右移 >>，把每个 bit 整体向左或向右移若干位。

课件给出 8 位整数示例（ch06 第 95 页）：

a = 0 0 0 0 1 0 1 1
b = 0 1 1 0 1 1 0 1
按位反:  ~a = 1 1 1 1 0 1 0 0
按位与:  a & b = 0 0 0 0 1 0 0 1
按位或:  a | b = 0 1 1 0 1 1 1 1
按位异或: a ^ b = 0 1 1 0 0 1 1 0

按位异或 ^ 可理解为“抛弃进位的加法”：

1 + 1 = 0;
0 + 0 = 0;
1 + 0 = 1;
0 + 1 = 1;

并由此具有可结合性与可交换性（课件 ch06 第 96、101 页）。

移位运算（课件 ch06 第 98 页）：左移 a << 1 右侧补 0；右移对于无符号数左侧补 0，对于有符号数 C 语言未规定（多数编译器复制符号位），老师建议避免对有符号数做右移。

移位的性质（对无符号整数）：左移 1 位相当于 ×2（不溢出时），右移 1 位相当于 ÷2（课件 ch06 第 99 页）。

位运算与赋值复合：&=、|=、^=、>>=、<<=，与别的赋值运算符优先级、结合性相同（右结合，倒数第二），例如 a &= b 等价于 a = a & b（课件 ch06 第 100 页）。

老师也提醒：&、|、^ 这几个符号有三个身份——位逻辑运算、取地址（一元 &）、逻辑运算（双目时才是位运算）；尤其 & 既可按位与又可取地址，含义不同要分清。

01:50:42—02:02:39 ｜ 位运算的运算性质与应用

本段讲位运算的性质（课件 ch06 第 101 页），要心里过一遍：

~0 = 0xFFFFFFFF
a & 0 = 0;          a & ~0 = a;
a | 0 = a;          a | ~0 = ~0;
a ^ 0 = a;          a ^ ~0 = ~a;
a & a = a;          a & ~a = 0;
a | a = a;          a | ~a = ~0;
a ^ a = 0;          a ^ ~a = ~0;
a ^ b ^ b = a;

老师点出：想让某个数与 0 做与/或/异或而不改变它——a & ~0 = a、a | 0 = a、a ^ 0 = a；想取反则 a ^ ~0 = ~a；自己异或自己得 0；与某数异或两次又还原。

例题/证明 9（01:55:23）｜ 用异或运算实现整数变量交换（无需临时变量）

题目／任务：不用中间变量，仅用三次异或完成两个 int 变量的交换。代码逐字符取自课件 ch06 第 101 页。

标准写法（临时变量）：

int a = 1, b = 2, temp;
temp = a;
a = b;
b = temp;

异或写法：

a = a ^ b;
b = b ^ a; // b 等于b ^ ( a ^ b ) 等于a
a = a ^ b; // a 等于( a ^ b ) ^ a 等于b

上面的代码等价于：

a ^= b; b ^= a; a ^= b;

也可以写在一个表达式里：a ^= b ^= a ^= b。

推导（课堂还原）：设 A、B 为两变量原值。第一步 a = a ^ b 后 a 变为 A^B；第二步 b = b ^ a 即 b = B ^ (A^B) = A（异或两次还原）；第三步 a = a ^ b 即 (A^B) ^ A = B。于是 a、b 的值互换。老师要求课后自己推导一遍。

例题/证明 10（02:00:19）｜ 用异或确定重复出现的整数

题目／任务：有 N+1 个变量存放 1,2,…,N，其中恰有一个整数重复了一次，如何快速找出它（课件 ch06 第 102 页）。

思路：逐对比较要 N(N−1)/2N(N-1)/2 次；求和再与 1+2+⋯+N1+2+\cdots+N 比较需 N+1N+1 次加减，但 N 很大时求和可能溢出；最保险的方法是用异或——把全部变量与 1,2,…,N 一起异或：

a0 ^ a1 ^ a2 ^ ... ^ aN ^ 1 ^ 2 ^ ... ^ N

没重复的数出现两次相互抵消为 0，剩下的就是那个重复的数。

02:02:39—02:10:14 ｜ sizeof 运算符与完整优先级表

本段讲长度运算符 sizeof（课件 ch06 第 103—104 页）：计算常量、变量或数据类型所占的字节数，是单目运算符。老师强调一个关键点：sizeof 在编译时执行，不在运行时。

例题/证明 11（02:03:16）｜ sizeof 运算符演示与“编译期求值”陷阱

题目／任务：验证 sizeof 给出的字节数，并理解它不执行括号内的运行时副作用。代码逐字符取自课件 ch06 第 103 页。

printf("int 字节数 = %d", sizeof(int));
printf("long 字节数 = %d", sizeof(long));
printf("long long 字节数 = %d", sizeof(long long));

运行可得：int 占 4 字节、long 占 4 或 8 字节（依平台）、long long 占 8 字节。

课堂补充演示（老师设 int a = 5; n = sizeof(++a);，再 printf 输出 a 的值）：++a 这一“加一”操作不会真的执行——因为 sizeof 在编译期就算好了结果（int 为 4 字节），运行时那一句只是把 4 赋给 n，a 仍等于 5。老师特意设计这个陷阱提醒大家：sizeof 是编译期运算符，括号里的表达式不产生运行时动作。

结论：sizeof(类型或变量) 得到字节数；它是编译期求值，不要指望它在运行期改变变量。

易错点：误以为 sizeof(++a) 会让 a 自增。

接着老师给出完整运算符优先级表（课件 ch06 第 104—106 页），从最高到最低：

  1. 初等类：()、[]、->、.
  2. 单目类（右→左结合）：!、~、+、-、(类型名)、&、++、--、sizeof
  3. 算术乘除：*、/、%
  4. 算术加减：+、-
  5. 移位类：<<、>>
  6. 关系比较：>、<、>=、<=
  7. 相等比较：==、!=
  8. 按位与：&
  9. 按位异或：^
  10. 按位或：|
  11. 逻辑与：&&
  12. 逻辑或：||
  13. 条件运算：? :（右→左结合）
  14. 赋值：=、+=、-=、*=、/=、%=、&=、^=、|=、>>=、<<=（右→左结合）
  15. 逗号运算符：,

老师还解释了位逻辑运算（第 8—10 级）为何排在逻辑运算（第 11—12 级）之前：位运算的结果是一个“丰富的”整数，而逻辑运算结果只有真假，所以位运算优先级更高。

02:10:14—02:25:16 ｜ 位运算应用：取第 k 位与输出二进制

本段讲位运算的实际应用（课件 ch06 第 107—111 页）。给定一个整数 n，要获取它的第 k 位（bit）是 0 还是 1：

  • 先产生掩码（mask）：1 << k，它只有第 k 位为 1，其余位全为 0。
  • 再做按位与：n & (1 << k)。该位为 0 则结果为 0，该位为 1 则与出 1——相当于一个“开关”把这一位抠出来。

例题/证明 12（02:10:14）｜ 输出整数的二进制位

题目／任务：从高位（如第 31 位）到低位（第 0 位）逐个输出一个整数的每一位。算法逐字符取自课件 ch06 第 107—111 页。

思路：用循环 for( k = hi; k >= low; k-- ) 产生掩码 1 << k，让 mask 与 n 做 & 运算；若结果全 0，说明该位为 0，否则为 1。

课堂现场演示（老师输入整数 2026，并把一个实数 3.14 的 32 个 bit 也打印出来）：验证单精度浮点数的存储格式——符号位为 0（正），阶码 8 位、尾数 23 位。老师按上节课浮点表示法手算核对：3.14 = 1.57 × 2，阶码值 = 128 − 127 = 1；尾数部分由 0.57 乘 2 取整得到 1001…，与程序打印的二进制一致，说明上节课讲的内容正确。

关于浮点数做位运算（课堂补充说明，不作掌握要求）：位运算只能作用于整数，而 3.14 是浮点数。老师演示了一种“欺骗”方法——取浮点数 x 的地址，用类型转换把它变成 int *（整数指针），再通过该整数指针把那 4 个字节当作整数读出来，从而能做位运算。这属于 C 语言能做的底层操作，但类型转换不安全，本节不作掌握要求，看懂即可。

结论：掩码 1 << k 配合 & 可抠出任意一位；浮点数的二进制需借助指针“按位 reinterpret”才能查看。

易错点：移位时把高位溢出丢弃、以为有符号右移一定补 0（实际多数编译器补符号位）；取第 k 位时要先移出掩码再做与运算，不能漏括号。
