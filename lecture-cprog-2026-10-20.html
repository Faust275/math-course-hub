00:03:27—00:09:00 ｜ 整数的二进制表示：原码、反码、补码

计算机用二进制码（0、1）表示所有数据。以 16 个 bit 的正整数为例，右起第 n 位的权重为2n2^n： 0 是 0000 0000 0000 0000， 1 是 0000 0000 0000 0001，……，215−12^{15}-1是 0111 1111 1111 1111。

但整数既要表示正的、也要表示负的。和浮点数一样，最高位（最左边的 bit）用作符号位：最高位为 0 表示正数，为 1 表示负数。

整数的表示有三种形式：

  1. 原码：最高位是符号位，其余表示数值。例如 −1 的原码是 1000 0000 0000 0001， −2 是 1000 0000 0000 0010。正负数之间只差一个符号位。
  2. 反码：正数的反码与其原码相同；负数的反码是对其原码逐位取反，但符号位除外。例如 −5 原码 1000 0000 0000 0101，反码 1111 1111 1111 1010。
  3. 补码：正数补码 = 反码 = 原码；负数补码 = 反码 + 1（符号位保持不变）。例如 −1 补码是 1111 1111 1111 1111， −2 补码是 1111 1111 1111 1110。

老师强调：先把这些当成“变戏法”一样记住，不必追问为什么这样定义（后面学了位运算再解释）。

00:09:00—00:16:04 ｜ 补码的特性、表示范围与整数溢出

补码的关键特点（以 16 位为例，从上到下递增 1）：

0111 1111 1111 1111   2^15-1     最大正数
...
0000 0000 0000 0010   2
0000 0000 0000 0001   1
0000 0000 0000 0000   0
1111 1111 1111 1111  -1
1111 1111 1111 1110  -2
...
1000 0000 0000 0001  -(2^15-1)
1000 0000 0000 0000  -2^15      最小负数
  • 从上到下递增 1，与数值关系一致、与符号无关；把正数、负数的计算统一起来了，运算时无需区分正负数。
  • 对于正整数：符号位为 0，数值部分补码 = 反码 = 原码。
  • 对于负数：符号位为 1，数值部分补码 = 反码 + 1。

表示范围（假设整数的 bit 数为 N ，采用补码）：

  • 最大正整数：2N−1−12^{N-1}-1（二进制 0111…1111）。
  • 最小负整数：−2N−1-2^{N-1}（二进制 1000…0000）。
  • 被表示的整数总数：2N−1−1+1+2N−1=2N2^{N-1}-1+1+2^{N-1}=2^N，没有浪费任何 bit（因为 N 个 bit 最多只能表示2N2^N个不同状态）。

对 C 语言 32 位 int：最大值231−1≈212^{31}-1\approx 21亿 4784 万，最小值−231≈−21-2^{31}\approx -21亿 4784 万。

溢出：最大正整数再加 1，会“逢二进一”变成 1000…0000，即从最大正数变成最小负数——结果完全错了。因此做整数运算时务必防止越界。

00:17:04—00:19:18 ｜ 平均数函数与整数溢出（面试例题）

老师提到一道面试/考题：写一个函数求两个整数 a 、 b 的平均值。如果直接 return (a+b)/2;，当 a 、 b 都接近最大正整数时，a+b 会先溢出变成负数，结果就错了。老师保留了更优写法（用位运算）作为悬念，提醒大家：做整数运算要小心加起来以后溢出。

例题/证明 1（00:17:04）｜ 平均数函数与整数溢出陷阱

题目／任务：写函数 int average(int a, int b) 求 a 、 b 的平均整数值。

思路：要求整数平均值（不是浮点）。直接 (a+b)/2 在 a 、 b 都接近 INT_MAX 时会先发生加法溢出。当堂只报名字、未展示完整代码，下面按标准 C 补出 [补全]，不是当堂讲的，仅作自学参照：

#include <stdio.h>
int average(int a, int b)
{
   return (a + b) / 2;
}

代码为整理者按标准 C 补出（[补全]），当堂只口述/报名字，课件未给出此程序。

  • 输入：例如 a = 2147483647，b = 2147483647。
  • 预期：平均值应为 2147483647。
  • 实际运行结果：a + b 溢出为负数，得到错误结果（并非 2147483647）。

结论：两个很大的正整数相加可能越过补码边界变成负数。求平均值不能简单地先加后除；稳妥做法（当堂留下悬念，未展开）是改用不会溢出的写法，如先各自右移再处理。

易错点：以为 (a+b)/2 总是安全；忽略整数加法本身就可能溢出。

00:19:18—00:25:53 ｜ 整数类型家族：short、int、long、long long 与无符号类型

C 语言里整数类型不止一种：

  • short [int]（短整型）：16 位，范围 ±3 万（−215∼215−1-\!2^{15}\sim 2^{15}-1）。
  • int：32 位（现代 64 位计算机上），范围 ±21 亿。注意 C 标准只规定 int 最多 32 位、最少 16 位，但现在计算机上都是 32 位。
  • long [int]（长整型）：C 标准规定一定 32 位，范围 ±21 亿（注意：不是 64 位）。
  • long long [int]（大长整型）：64 位，范围 ±900 亿亿（−263∼263−1-\!2^{63}\sim 2^{63}-1）。
  • 在 64 位计算机系统上，long 也是 64 位；若想明确 64 位，应使用 long long。

short、int、long、long long 都可以写成省略 int 的形式（short、long、long long）。char 也是整数类型（8 位，一个字节）。

无符号整数：很多整数没有负值意义（如个数、长度），可用无符号整数（unsigned）。它没有符号位，全部 bit 用来存正整数的原码，所以补码与原码相同。

  • N 个 bit 的无符号整数范围：[0,2N−1][0,\,2^N-1]，共2N2^N个。
  • 每种有符号整数都有对应的无符号类型：unsigned short [int]、unsigned [int]、unsigned long [int]、unsigned long long [int]。

00:25:22—00:28:33 ｜ sizeof 运算符与类型转换运算符的区别

想知道一个类型占多少字节，用 sizeof 运算符（不是函数，写法像函数）。课件第 13 页给出：

printf("int 字节数 = %d", sizeof(int));
printf("long 字节数 = %d", sizeof(long));
printf("long long 字节数 = %d", sizeof(long long));

代码取自课件 ch06.txt 第 13 页

sizeof 也可作用于常量、变量，如 sizeof 4.5、sizeof x；若 x 是 int 则等价于 sizeof(int)，若是 float 则等价于 sizeof(float)。

注意区分两种“把类型括起来”的写法：

  • 类型转换运算符：(类型名)表达式，如 (int)1.999 得到 1（把值转成该类型，只转“值”，不转变量）。
  • sizeof 运算符：sizeof(类型名) 或 sizeof 表达式。
  • 二者都把类型名用括号括起来，但含义完全不同：一个是“转换值的类型”，一个是“求占用字节数”。

00:28:44—00:34:48 ｜ 无符号整数与整数常量的进制表示

计算机内部用二进制存整数，但 C 语言语法不支持用二进制写整型常量。C 语言支持的整型常量写法：

  • 十进制常量：不能以 0 开头（数字 0～9 组成）。
  • 八进制常量：以 0 开头，由数字 0～7 组成；右起第 k 位权重为8k8^k。
  • 十六进制常量：以 0x 或 0X 开头，由 0～9、a～f（或 A～F）组成；右起第 k 位权重为16k16^k。
  • 进制数值前面都可加 +、- 表示正负。

例：010 是八进制，等于十进制 8；10 是十进制 10；-023 是八进制负常量，等于十进制 −19 ；0x16 是十六进制，等于十进制 22；0x12 等于十进制 18；0xFF 等于十进制 255。

十六进制与二进制互相转换很方便：每 4 个二进制位对应 1 个十六进制位（如 0xABCF → 1010 1011 1100 1101）。

00:34:48—00:38:14 ｜ 八进制、十六进制与二进制的互相转换

  • 十六进制 → 二进制：把每个十六进制数字展开成 4 位二进制（如 0xABCF：A→1010，B→1011，C→1100，F→1111）。
  • 二进制 → 十六进制：从右往左每 4 位一组拼成十六进制数字。
  • 二进制 → 八进制：每 3 位一组；八进制 → 二进制：每个八进制数字展开成 3 位。
  • 十进制 → 二进制/八进制/十六进制：不断除以对应基数（除 2、除 8、除 16），比一直除 2 更快。

00:38:14—00:41:02 ｜ 整数常量的后缀

给整型常量加后缀表示它的类型：

  • 无符号：U/u（unsigned）。
  • 长整型：L/l（long）。
  • 无符号长整型：UL/LU、ul/lu（unsigned long）。
  • 大长整型：LL（long long）。

例：-12L、12u、034U、12LU、0X567LU。

00:41:02—00:52:11 ｜ 短整数溢出截断：short n = 123456789

若定义 short n = 123456789;，n 得不到真实值，而是得到 -13035。原因：123456789 = 0x75bcd15（占 4 个字节），而 short 只有 2 个字节，超出部分被截断，只保留低位的 2 个字节 cd15。cd15 的第一个 bit 为 1（符号位为负），按补码还原得到 −13035 。

例题/证明 2（00:41:02）｜ 短整数溢出截断：short n = 123456789 → −13035

题目／任务：解释 short n = 123456789; 为什么 n = -13035。

思路：常数 123456789 是 4 字节（0x75bcd15），赋给 2 字节的 short 时，保留低位的 2 个字节 cd15，高位字节被舍弃。

下面这段程序当堂只口述了赋值与结果，课件第 20 页给出的是分析过程（非完整可运行程序），下面按标准 C 补出一个可运行版本 [补全]，不是当堂展示的代码，仅作自学参照：

#include <stdio.h>
int main(void)
{
   short n = 123456789;
   printf("n = %d\n", n);
   return 0;
}

代码为整理者按标准 C 补出（[补全]），当堂只口述结果，课件未给出此程序。

输入：无（123456789 是字面常量）。

输出／运行结果：

n = -13035

逐步推导（依据课件第 20 页）：

  1. 123456789 = 0x75bcd15，对应 4 个字节：07 5b cd 15（高位在前）。
  2. short 只保留低 2 字节 cd 15，即 cd15（二进制 1100 1101 0001 0101）。
  3. 最高 bit 为 1 → 负数（补码）。数值部分：反码 = 100 1101 0001 0100，原码 = 011 0010 1110 1011。
  4. 原码写成十进制：3×163+2×162+14×16+11=130353\times16^3+2\times16^2+14\times16+11 = 13035，故 n = -13035。

结论：从长整型到短整型，规则是保留低位字节、丢弃高位超出的字节（即截断）；如果原值较大，截断后可能变负。

易错点：以为 short 会自动“缩小”为你想要的值；忘记截断是按字节、从低位保留。

00:52:11—01:06:56 ｜ 有符号整数与无符号整数的赋值（内存拷贝）

整数与无符号整数之间运算、赋值要特别小心。看一个例子（完整代码在课件第 22 页，逐字符照抄）：

例题/证明 3（00:54:47）｜ 有符号与无符号整数赋值（int m = 1, n = −1）

题目／任务：把有符号整数 m=1、n=-1 分别赋值给无符号变量 um、un，并用 %d、%u、%x 观察输出。

代码（逐字符取自课件 ch06.txt 第 22 页）：

#include <stdio.h>
int main(void)
{
int m = 1, n = -1;
unsigned int um, un;
um = m;
un = n;
printf(" m = %d,  n = %d\n", m, n);
printf("um = %u, un = %u\n", um, un);
printf(" m = 0x%08X,  n = 0x%08X\n", m, n);
printf("um = 0x%08X, un = 0x%08X\n", um, un);
return 0;
}

代码取自课件 ch06.txt 第 22 页

输出／运行结果（逐字符取自课件 ch06.txt 第 22 页）：

 m = 1,  n = -1
um = 1, un = 4294967295
 m = 0x00000001,  n = 0xFFFFFFFF
um = 0x00000001, un = 0xFFFFFFFF

原理讲解：

  • 整数类型之间的赋值，做的是内存拷贝——把右边变量（或值）的二进制 bit 直接复制到左边变量的内存中，不管它是有符号还是无符号、是长是短。
  • n = -1 在内存里是 32 个 1（0xFFFFFFFF）。把它拷贝给 un（无符号）后，un 里的 bit 仍是 32 个 1；用 %u 解释成无符号整数，就得到最大的无符号整数 4294967295。
  • 用 %d 解释这 32 个 1，则按有符号补码得到 -1。所以同一个 bit 模式，怎么解读就得到什么结果。
  • %08X 中的 08 表示最少 8 位、不足左侧补 0；X 表示十六进制大写字母。

老师点出的意义：混合使用 int 与 unsigned int 时要特别小心——它们在内存里可能是完全相同的 bit，但按不同格式解读会得到天差地别的值。

题外话（学习方法提醒，属于有效信息）：大学里没人盯着你学，要主动学、靠作业检验自己是否真掌握；老师借游戏与含糖饮料类比——若只“被游戏消费”或只靠糖获得短暂兴奋，长期无益；若能思考“游戏画面是怎么做出来的”，就会变成学习动力。这部分是励志与学习方法提醒，非知识点。

01:07:15—01:13:39 ｜ 浮点数的存储：小数二进制与 IEEE 754 表示

十进制小数转二进制：整数部分“除以 2 取余数”，小数部分“乘以 2 取整数”。

例：把 6.625 转二进制。

  • 整数 6 ：除以 2 取余 → 110。
  • 小数 0.625 ： 0.625×2=1.25 取整 1； 0.25×2=0.5 取整 0； 0.5×2=1.0 取整 1，结束。得到 0.101。
  • 故6.625=(110.101)26.625 = (110.101)_2。

例：把 1.7 转二进制。

  • 0.7×2=1.4 取整 1； 0.4×2=0.8 取整 0； 0.8×2=1.6 取整 1； 0.6×2=1.2 取整 1； 0.2×2=0.4 取整 0；……一直循环，得到二进制的无限循环小数 1.10110…。

这说明：简单如 1.7 在计算机里无法精确表示（会截断）。而 6.625 没有误差。

IEEE 浮点数表示（课件第 26 页）：一个浮点数由 符号 S（1 bit）＋ 阶码 E ＋ 尾数 M 组成。

  • float：1 + 8 + 23 位。尾数默认隐藏一个前导 1（尾数 = 1.M，当阶码不全为 0 时），故有效位约 7～8 位十进制。
  • double：1 + 11 + 52 位。尾数有效位约 15～16 位十进制。
  • 阶码采用移码：对 float，E = 阶码 − 127（阶码 8 位，范围 0∼255 ，故Emin=−127E_{\min}=-127、Emax=128E_{\max}=128）；对 double，E = 阶码 − 1023（Emin=−1023E_{\min}=-1023、Emax=1024E_{\max}=1024）。
  • 数值 = S×2E×1.MS \times 2^{E} \times 1.M（或阶码全 0 时为S×2E×0.MS\times2^{E}\times0.M）。

01:13:39—01:24:49 ｜ 浮点数的范围、精度与实数常量

取值范围：float 约±[10−38,1038]\pm[10^{-38},\,10^{38}]；double 约±[10−308,10308]\pm[10^{-308},\,10^{308}]。

  • float 的103810^{38}怎么来：最大 E=128 ，再乘 1.…≈2128≈1038.42^{128}\approx 10^{38.4}，故约103810^{38}。
  • double 的1030810^{308}同理：21024≈10307.22^{1024}\approx 10^{307.2}，约1030810^{308}。

精度与取值范围是两个不同概念：

  • float x = 1234567.89; 虽在取值范围内，但 float 只有 7 个有效数字，无法精确表达。
  • float y = 1.2e55; 精度要求不高，但超出取值范围（103810^{38}），也无法精确表示。

并非所有实数都能精确表示：float 最多表示2322^{32}个浮点数，double 最多2642^{64}个——相对连续实数几乎是“九牛一毛”，且数值越大误差越大。

实数常量的表示：

  • 普通表示：符号 + 整数部分 + 小数点 + 小数部分，如 -12345.678。
  • 科学计数法：符号 + 尾数 e/E 指数，如 -1.2345678E5；普朗克常量6.026×10−276.026\times10^{-27}可写成 6.026E-27 或 60.26E-28。
  • 实型常量的类型都是 double；要表示 float 常量，加后缀 f，如 3.14f、5f。

01:24:49—01:31:49 ｜ 字符类型、ASCII 码与转义字符

char 也是整数：占 1 个字节，存的是该字符的 ASCII 码值（如 'A' 的 ASCII 是 65）。所以 char 本质上是长度为 1 字节的短整数，可以像整数那样做四则运算、用于 switch 等。其取值范围是 [−128,127] （0～127 可作 ASCII 字符，负的部分是负整数）。

转义字符：C 语言把反斜杠 \ 定义为转义字符，用来把“正常字符”变成“特殊字符”，或把“特殊字符”变成普通字符（课件第 34 页）：

字符 含义
\\ 反斜杠字符本身 \
\n 换行符
\t 横向跳格符（制表符）
\" 双引号字符本身 "
\' 单引号字符本身 '
\ddd 1～3 位八进制数作为 ASCII 码所代表的字符
\xhh 1～2 位十六进制数作为 ASCII 码所代表的字符

注意：不要把转义字符的反斜杠和 printf 里的 % 混为一谈。% 是 printf/scanf 约定的格式控制字符；在 printf/scanf 里用 %% 表示一个百分号，和用 \\ 表示反斜杠方法雷同；而在其他时候直接用 '%' 表示百分号，不需要任何转义。

01:56:26—02:01:15 ｜ 键盘缓冲区与标准输入流 stdin

键盘输入与 scanf 的关系（课件第 51～52 页）：

  • 键盘缓冲区：保存键入的字符序列。
  • 标准输入流 stdin（standard input）：为 scanf、getchar 等提供字符流；它可以对应键盘缓冲区，也可以对应某个文件。

流程：

  1. 用户键入字符，存入键盘缓冲区。
  2. 按下回车（return），产生一个换行符 \n 存入缓冲区。
  3. 缓冲区收到 \n 后，把字符序列（含 \n）转移到 stdin。
  4. scanf/getchar 从 stdin 最前面的字符开始读取。
  5. scanf 成功读取数据后，把已消耗的字符从 stdin 自动删除；遇到不满足格式要求的字符则终止运行，该字符仍留在 stdin。

若 stdin 为空，scanf/getchar 会停下来等待用户输入——这就是程序“卡住等你输入”的原因。

02:01:15—02:03:57 ｜ scanf 的格式字符 %d %f %lf %c %n

scanf 的格式字符（课件第 53 页）：

  • %d：读十进制整数（int）。
  • %f：读单精度浮点数（float）。
  • %lf：读双精度浮点数（double）。
  • %c：读一个字符（char）；不会跳过任何空白字符（空格、回车、制表符都有效）。
  • %n：记录到目前为止从 stdin 消耗的字符个数（含读入和跳过的）。

例外：读取 %d/%f/%lf 等数值时，会自动跳过数据前面的空白字符（空格、换行、制表符）；但 %c 读字符不跳过空白。普通字符中，一个空格或 \n 可匹配 0～多个连续空白字符。

02:11:30—02:22:04 ｜ 数据类型转换：强制类型转换与自动类型转换

强制类型转换（课件第 63～64 页）：(类型名)表达式。它是单目运算符，优先级高于一切双目运算符。它把“值”转换成指定类型，得到新值——不能把变量本身变成另一种类型（变量在内存中的大小是固定的）。

例题/证明 19（02:13:05）｜ 强制类型转换：float x = 1.5 的四种输出

题目／任务（课件第 65 页）：观察以下四条 printf 的输出差异。

代码（逐字符取自课件 ch06.txt 第 65 页）：

float x = 1.5;
printf("%f", (int)x + 1.8);
printf("%f", (int)(x+1.8));
printf("%d", (int)x);
printf("%d", x);

代码取自课件 ch06.txt 第 65 页

讲解与运行结果：

  1. (int)x + 1.8：(int)x 先把 1.5 转成整数 1，再 +1.8 得 2.8，按 %f 输出 2.800000。
  2. (int)(x+1.8)：先算 x+1.8 = 3.3，再转 int 得 3，按 %f 输出 3.000000。
  3. (int)x 得 1，按 %d 输出 1。
  4. printf("%d", x);：格式符 %d 与参数类型 float 不一致——printf 不会按 % 做类型转换，而是把 x 的 bit 直接按整数解释，输出一个“怪怪的”无意义值。只有当 % 格式与参数类型一致时输出才正确。

自动类型转换（课件第 66～67 页）：不同类型混合运算时，系统按规则先转成相同类型再运算；无论哪种转换，转的都是“值的类型”，不是变量的类型。规则要点：

  • 赋值运算：右边类型转成左边类型再赋给左边；右边更长会丢失精度（产生警告）。
  • 函数调用：实参隐式转成形参类型；返回值隐式转成函数返回类型。
  • 浮点运算都以双精度 double 进行（float 操作数先转 double，结果再转回 float）——保证精度、提高速度。
  • char、short 参与运算先转成 int。
  • 有符号整型与无符号整型混合运算：有符号型要转成无符号型，结果也是无符号的。

02:22:04—02:25:06 ｜ 有符号与无符号混合运算例题

例题/证明 20（02:22:04）｜ 有符号与无符号混合运算：int a = −10, unsigned b = 5

题目／任务（课件第 67 页）：判断 if ((a+b) > 0) 是否成立并输出什么。

代码（逐字符取自课件 ch06.txt 第 67 页）：

int a = -10; unsigned b = 5;
if ((a+b) > 0) printf("Hello\n");
else printf("World\n");

代码取自课件 ch06.txt 第 67 页

输出／运行结果（逐字符取自课件 ch06.txt 第 67 页）：

Hello

讲解：a（int）与 b（unsigned）运算时，a 被转换成无符号整数——-10 的 32 个 1 被解释成一个很大的无符号正整数，加上 5 后仍是很大的正整数（远 > 0）。所以 (a+b) > 0 为真，输出 Hello。这与数学上 a+b = -5 的直觉完全相反。

易错点：有符号整数与无符号整数混合运算时，有符号的会被转成无符号，结果也是无符号；a+b 不等于 0 时一定 > 0。这也是常考题目。类似地，for(i=1; i<=n; i++) 中若 n 是无符号整数、而 i 是有符号整数，比较时也易出错，要特别小心。
